## Background

Phase 1 BYOD requires users to install supported coding agents without
administrator rights. Today Agentdesktop only discovers and configures agents
that are already installed: there is no catalog-driven installer, no job
protocol, no install receipt, and no uninstall path. The controller cannot ask a
device to install or remove anything.

This Story adds a user-level install/uninstall job framework with macOS as the
first platform. It depends on STORY-20261026089ea5bea624 for the signed catalog
and local configuration authority; it MUST NOT execute anything that is not a
verified catalog artifact. Windows and Linux installers are out of scope.

## Requirements

### R1: Job protocol and lifecycle (MUST)

The fleet protocol MUST add an `AgentJob` message for `install`, `uninstall`,
and `update`, plus a `JobStatus` message. Every job MUST carry `job_id`,
`attempt`, `idempotency_key`, `origin` (`admin` or `local`), `requested_by`,
`catalog_id`, `catalog_revision`, `catalog_hash`, `agent_id`, `version`,
`action`, and `deadline`. Jobs MUST persist on both controller and daemon,
survive restart/reconnect, and follow only the transitions in the Technical
Design table. At most one job per device may execute at a time.

Duplicate delivery with the same `job_id` MUST be deduplicated; a terminal status
MUST be replayable; a late result from an older `attempt` MUST NOT change the
job. `unchanged` MUST require both a version/detection match and a valid receipt
integrity check. The daemon MUST also accept local-origin install/uninstall
requests through its local API; they use the same catalog, executor, and audit
fields but do not require controller dispatch. Local-origin jobs MUST be
persisted locally and reported to the controller with `origin=local` when a
connection exists; if no controller is connected, the local audit record remains
authoritative and is uploaded on reconnect.

### R2: User-level macOS installation (MUST)

The daemon MUST install only into user-writable locations: `~/Applications` for
application bundles, `~/.local/bin` for command-line launchers, and a private
managed directory under the daemon state directory. It MUST NOT call `sudo`,
write under `/Applications`, `/Library`, `/usr`, or modify a shell profile.
A `.pkg` requiring Installer authorization MUST be refused.

### R3: Cross-file atomic install, journal, and recovery (MUST)

The daemon MUST download into a private temporary directory (mode 0700), verify
the artifact, extract into a versioned staging directory, and publish payload,
application bundle, and launcher through a persisted journal. The commit point
MUST be the atomic write of the `committed` receipt after all paths are
published. Before that point, recovery MUST roll back and leave the old committed
state intact; after it, recovery MUST roll forward cleanup. A crash at any step
MUST leave either the complete old state or the complete new state, never a
mixed one. Reinstalling the same version MUST return `unchanged` only when
detection and receipt integrity both pass.

### R4: Uninstall safety and object verification (MUST)

Uninstall MUST be allowed only for an agent with a managed install receipt.
User-installed agents MUST be refused with a structured error. The receipt MUST
record, per path, the object type, SHA-256 for files, symlink target, size, and
mtime where available. Before deletion the daemon MUST verify the current object
still matches the receipt; a replaced, modified, or re-pointed object MUST return
`conflict` and MUST NOT be deleted unless the caller supplies an explicit
`allow_modified` consent. Symlinks MUST be inspected with `lstat`: a managed
launcher link is removed only when its target matches the receipt, and the link
is never followed. Ancestor paths MUST be checked for symlink traversal. User
configuration is preserved by default, and a dry-run reports paths without
deleting them.

### R5: Artifact verification and catalog binding (MUST)

Before extraction or execution, the daemon MUST verify the catalog signature,
the artifact SHA-256, the artifact signature, the artifact size cap, and the
download URL scheme/host allowlist. The job MUST bind `catalog_id`,
`catalog_revision`, and `catalog_hash`; the daemon MUST reject a job when its
verified catalog no longer matches, and a catalog change while a job is queued
MUST fail with `catalog_changed` and require re-approval. Archive extraction MUST
reject absolute paths, `..` traversal, symlink escapes, duplicate entries, and
entry-count/size limits. The daemon MUST reuse the S1 catalog verification path
rather than implement a second one. Uninstall MUST use the receipt, not the
current catalog, so an agent removed from the catalog remains uninstallable.

### R6: Detection and inventory (MUST)

Before and after a job, the daemon MUST detect the agent's installed version,
path, and source (`managed`, `user`, or `unknown`) and report the result to the
controller. If an agent is already installed by the user, the daemon MUST mark it
`user` and MUST NOT offer uninstall or silently replace it.

### R7: Failure reporting and diagnostics (MUST)

A failed job MUST report a stable error code, a redacted message, a stderr tail
limited to 4 KiB, and a small environment snapshot (OS, architecture, free disk,
target root, whether the path is user-writable). It MUST NOT include secrets,
environment variables, file contents, or full paths containing a user name where
a redacted path is sufficient. Retryable and non-retryable failures MUST be
distinguishable.

### R8: Platform gating and capability negotiation (MUST)

macOS is the only executable platform in this Story. The daemon MUST report
`user_install_macos` as a capability; Windows and Linux MUST report it as
unsupported. The controller MUST disable install/uninstall actions for devices
that do not report the capability.

### R9: Audit, authentication, and tests (MUST)

The controller MUST record `requested_by`, `origin`, device, agent, catalog
revision/hash, and the final result for every job. Admin-origin requests MUST
carry an authenticated actor (R10). Unit tests MUST cover the state machine
including cancel/expire/lost-ack/late-result, idempotency, signature/hash
rejection, path traversal, symlink escape, cross-file crash recovery, atomic
upgrade, uninstall refusal, receipt conflict, dry-run, and structured
diagnostics. Integration tests MUST use local fake artifacts and MUST NOT require
network access.

### R10: Admin authentication and actor attribution (MUST)

The controller admin API MUST NOT accept unauthenticated requests. Phase 1 MUST
support at least one verified mode:

- `oidc`: validate an OIDC bearer token against the configured issuer and
  audience;
- `trusted_proxy`: require mTLS from the SaaS gateway plus a short-lived,
  replay-protected, gateway-signed actor assertion.

A plain `X-User`, `X-Email`, or similar header MUST NOT be trusted. Phase 1
implements `oidc`; the `trusted_proxy` contract is defined here but its
implementation is out of scope. The resolved actor is the verified `issuer` +
`subject` (plus optional roles/groups); for a local-origin job the actor is the
local OS uid/username recorded by the daemon. RBAC MUST require a configured
operator role for enqueue/cancel/delete; denied requests MUST be audited. If no
admin auth mode is configured, admin write endpoints MUST return 403 and log the
misconfiguration; local-origin jobs remain available.

## Technical Design

**Job lifecycle.** The controller persists a job in `agent_jobs` with
`idempotency_key`, `attempt`, and `origin`, and transitions it to `dispatched`
when sent over `Connect`. The daemon persists the same job in its state
directory, acknowledges `accepted`, executes, and reports terminal status. On
reconnect, the daemon calls `ListPendingJobs` and either resumes a safe step or
reports an `interrupted` failure with a retryable flag.

| From | Event | To | Rule |
|------|-------|----|------|
| queued | dispatch | dispatched | Controller sends the current attempt. |
| queued | cancel | cancelled | Admin or local user before dispatch. |
| queued | deadline | expired | No dispatch before the deadline. |
| dispatched | accept | accepted | Daemon persists before acknowledging. |
| dispatched | no ack by deadline | expired | Controller may redispatch after expiry only with a new job. |
| accepted | start | running | Executor acquires the device lock. |
| accepted | cancel | cancelled | Before execution starts. |
| running | success | succeeded | Commit point completed. |
| running | failure | failed | Includes a retryable flag and error code. |
| running | cancel | cancel_requested | Executor checks between steps. |
| cancel_requested | before commit point | cancelled | Staged paths rolled back. |
| cancel_requested | after commit point | succeeded/failed | Cancel is recorded as ignored, never a mixed state. |
| non-terminal | duplicate dispatch | unchanged | Same `job_id`; replay current status. |
| terminal | reconnect | terminal | Replay the terminal status; no re-execution. |
| terminal | late older `attempt` result | unchanged | Record as stale and ignore. |

**Install layout.**

```
~/Library/Application Support/agentdesktop/agents/<agent-id>/<version>/  (payload)
~/Applications/<Agent>.app                                                (user bundle)
~/.local/bin/<agent>                                                      (launcher symlink)
<state-dir>/installs/<agent-id>/state.json                                (journal + receipt, 0600)
<state-dir>/installs/<agent-id>/.old-<job-id>/                            (replaced bundle)
<state-dir>/downloads/<job-id>/                                           (temp, 0700)
```

**Transaction and recovery.** The journal `state.json` contains a `committed`
receipt and an optional `pending` record with target version, staging paths, old
receipt hash, swapped paths, and the step reached. Install steps are: (1) write
`pending`; (2) stage payload; (3) publish the versioned payload directory; (4)
swap the application bundle and launcher symlink; (5) atomically write the
`committed` receipt — the commit point; (6) remove the old version and `.old-*`
directories. On startup, a `pending` without `committed` is rolled back to the old
receipt; a `committed` with a stale `pending` is rolled forward by repeating the
idempotent cleanup. The receipt records every created path and its source;
uninstall trusts only the receipt.

**Download and extraction.** Reuse `reqwest` for HTTPS, `sha2` for hashes, and
`aws-lc-rs` for Ed25519. Add `tar` and `flate2` as **direct** workspace
dependencies for `.tar.gz` extraction (`flate2` is only transitive today). No
shell is used; the installer invokes no external command except platform tools
that are explicitly catalogued and argument-arrayed.

**Uninstall.** Read the receipt, verify each current object against its recorded
type, hash, symlink target, size, and mtime, and refuse changed objects with
`conflict` unless `allow_modified` consent is supplied. Remove in reverse order,
keep agent configuration directories, and write an audit event with the removed
paths. `lstat` is used so a managed launcher symlink is removed as a link and
never followed; ancestor paths are checked for symlink traversal.

**Controller.** A new `jobs.rs` owns the state machine and dispatch; a new
`admin_auth.rs` validates OIDC tokens or a trusted-proxy actor assertion and
resolves the operator role; `admin.rs` gains authenticated job creation/status
endpoints; `database.rs` gains the queries; a migration adds `agent_jobs` and
`agent_install_receipts`. Audit events are written for every requested state
change. If no admin auth mode is configured, write endpoints return 403.

**Daemon.** A new `jobs.rs` serializes execution, `manifest.rs` validates the
artifact, `installer/macos.rs` performs install/uninstall, and `remote.rs`
handles dispatch and reconnect. Local-origin requests enter through the local
API and use the same executor. The S1 catalog is the only source of installable
entries; uninstall uses the receipt.

**Engineering concerns.** Candidate signals confirmed for this change:

| Concern | Decision |
|---------|----------|
| concurrency | One active job per device; a daemon-local mutex plus a persisted job state. |
| error-recovery | Idempotency key, attempt, retryable/non-retryable codes, reconnect reconciliation, late-result rejection. |
| data-consistency | Journal with a single commit point; crash recovery rolls back before the receipt write and forward after it. |
| write-safety | Versioned staging, atomic renames, receipt object verification, dry-run uninstall, no user-data deletion. |
| dependency-supply-chain | Signed catalog, SHA-256, artifact signature, HTTPS allowlist, size caps. |
| graceful-shutdown | Persist running job; on restart report interrupted or resume a safe step. |
| observability | Job state, error code, redacted stderr tail, environment snapshot, audit event. |
| security | No sudo, no shell, no system paths, no arbitrary URLs or commands. |
| authentication-authorization | Admin OIDC/trusted-proxy actor, operator role, local OS uid attribution, deny-by-default. |

### Lateral Scan Results

- **Operation:** apply agent configuration. **Existing implementation:**
  `Provider`/`Reconciler`. **Assessment:** reuse for post-install configuration;
  it is not an installer.
- **Operation:** verify a signed catalog artifact. **Existing implementation:**
  S1 `catalog` module. **Assessment:** reuse; do not add a second verifier.
- **Operation:** install/uninstall a coding agent. **Existing implementation:**
  none — no installer, job, or receipt modules exist. **Assessment:** new
  subsystem is justified; the provider layer stays unchanged.

## Trust Boundaries

- Admin request → OIDC token validation or mTLS trusted-proxy assertion →
  resolved `issuer`+`subject` → operator-role check → job enqueue.
- Local request → local socket permissions → local OS uid/username →
  local-origin job; no controller authentication is implied.
- Controller job → device mTLS/OIDC authentication → capability check →
  catalog revision/hash match → daemon job executor.
- Catalog artifact URL → HTTPS + host allowlist + size/timeout caps → SHA-256
  and Ed25519 verification → private temp directory.
- Archive → absolute-path, `..`, symlink, duplicate-entry, and size validation →
  versioned staging directory → journaled publish with one commit point.
- Install receipt → type/hash/symlink/size/mtime verification → uninstall removes
  only unchanged receipted objects; user configuration is preserved.
- Job diagnostics → redaction (secrets, environment, file contents) →
  controller database and device detail UI.

## Acceptance Criteria

### AC1: Only cataloged agents can be installed and jobs bind the catalog (R1, R5)

- **Given** a job for a cataloged agent, a job for an id not in the catalog, and a job whose `catalog_revision`/`catalog_hash` no longer matches the daemon's verified catalog
- **When** the daemon receives all three
- **Then** the cataloged job proceeds, the unknown job fails with `unknown_agent`, and the stale-binding job fails with `catalog_changed` before any download or write

### AC2: Verification failure aborts before execution (R5)

- **Given** an artifact whose SHA-256 or Ed25519 signature does not match the catalog entry
- **When** the daemon downloads it
- **Then** it reports `checksum_mismatch` or `signature_invalid`, deletes the temp artifact, and leaves the previous install and receipt unchanged

### AC3: Installation stays user-level (R2)

- **Given** a macOS user without administrator rights
- **When** a valid install job runs
- **Then** files are written only under `~/Applications`, `~/.local/bin`, and the daemon state directory, no `sudo` or Installer authorization is requested, and a system-path target is refused

### AC4: Install, upgrade, and crash recovery are consistent (R3)

- **Given** version 1 installed, a job for version 2, a repeat of version 2, and a crash injected after payload publish but before the receipt write
- **When** the jobs and recovery run
- **Then** version 2 is published only after successful staging, the repeat returns `unchanged` only when detection and receipt integrity pass, the crash restores version 1, and a crash after the receipt write finishes cleanup without a mixed state

### AC5: The lifecycle handles duplicates, cancellation, expiry, and late results (R1)

- **Given** two jobs delivered concurrently, a queued cancel, a running cancel, an unacknowledged dispatch past its deadline, and a late result from an older attempt
- **When** the daemon and controller process them
- **Then** only one executes, the queued job becomes `cancelled`, the running job cancels only before the commit point, the unacknowledged job expires, and the late result is recorded as stale without changing the state

### AC6: Uninstall verifies the current object and respects ownership (R4, R6)

- **Given** a managed agent with unchanged receipted paths, a managed agent whose launcher was replaced by the user, a user-installed agent, and a dry-run request
- **When** uninstall is requested for each
- **Then** unchanged paths are removed, the replaced launcher returns `conflict` without `allow_modified`, the user-installed agent is refused, and the dry-run lists paths without deleting them

### AC7: Failures are actionable (R7)

- **Given** a download timeout, a permission error, and a disk-full condition
- **When** each job fails
- **Then** the status contains a stable code, a redacted message, a bounded stderr tail, an environment snapshot, and a retryable flag

### AC8: Unsupported platforms cannot receive install jobs (R8)

- **Given** a Windows or Linux daemon without `user_install_macos`
- **When** an install job is attempted
- **Then** the controller disables the action and the daemon rejects the job as unsupported

### AC9: The job path is covered by tests (R9)

- **Given** the Story's test suite
- **When** it runs without network access
- **Then** state transitions, idempotency, verification failures, traversal/symlink rejection, cross-file crash recovery, receipt conflict, uninstall refusal, dry-run, and diagnostics are covered and pass

### AC10: Admin and local origins are authenticated and attributed (R10)

- **Given** no admin auth configuration, a verified OIDC administrator with the operator role, an administrator without the role, a plain spoofed `X-User` header, and a local OS user
- **When** each attempts to enqueue or run an install
- **Then** the unauthenticated/spoofed/roleless requests are denied and audited, the operator is allowed with `requested_by` set to the verified issuer+subject, and the local user can install a cataloged agent through the local API with `requested_by` set to the local uid

## Target Call Chain

1. **Admin enqueue.** Admin HTTP `POST /api/v1/devices/{id}/jobs` →
   `admin_auth.rs` (OIDC token or trusted-proxy assertion) → actor + operator
   role → `jobs.rs` → `database.rs` (`agent_jobs`, state `queued`) → audit event.
2. **Local enqueue.** Desktop app → local socket →
   `POST /v1/agents/{id}/jobs` → daemon `jobs.rs` → local OS uid recorded as
   `requested_by`; no controller authentication is implied.
3. **Dispatch.** Controller `service.rs` `Connect` stream → `AgentJob`
   (`catalog_revision`/`catalog_hash`) → daemon `remote.rs` → `jobs.rs`
   (persist, `accepted`).
4. **Execute.** `jobs.rs` → `manifest.rs` (catalog id/revision/hash, signatures,
   SHA-256, URL allowlist, size cap) → `installer/macos.rs` (download to temp,
   verify, journaled install, commit point, receipt).
5. **Detect and report.** `installer/macos.rs` → provider detection → inventory
   → `JobStatus` (`succeeded`/`failed`) → controller `service.rs` →
   `database.rs` → device detail API.
6. **Reconnect.** Daemon `remote.rs` → `ListPendingJobs` → resume a safe step or
   report `interrupted`; duplicate `job_id` is deduplicated and a late older
   attempt is recorded as stale.

## Open Questions

- Q1: macOS artifact format for Phase 1: `.tar.gz` containing an `.app` bundle or
  CLI binary. `.pkg` and `.dmg` requiring Installer/UAC authorization are
  refused until a user-scope installer is validated.
- Q2: Whether `~/.local/bin` is on the user's `PATH`; Phase 1 reports it rather
  than modifying shell profiles.
- Q3: Signature key rotation follows the S1 catalog key-id mechanism; the
  rotation runbook is a release prerequisite.

## Out of Scope

- Windows and Linux installers.
- System-level installation, `sudo`, or elevation.
- Code-signature verification of macOS bundles beyond catalog SHA-256/Ed25519.
- Desktop UI for job progress (a later Story).
- Chat-based failure diagnosis (a later Story).
- Auto-update of the installed agent beyond catalog-driven `update` jobs.
- The `trusted_proxy` admin auth mode (contract defined in R10; OIDC is
  implemented first).
