## Background

Installing the packaged macOS build exposed four user-visible defects: the
Agents page crashed because the daemon omitted catalog fields the UI required,
the Agents page lacked a usable empty/error state, the Assistant page rendered
unstyled action buttons, and the desktop app could show no window after the
daemon fallback or after the user closed and reopened it.

## Defects and fixes

### D1: `/v1/agents` omitted `versions` and `detection`

- Target: `crates/agent/src/api.rs` — `agents` handler, new `agent_json`.
- The response now includes `versions` and `detection` from the signed catalog
  entry. The UI still tolerates a missing list with `(agent.versions ?? [])`.
- Regression test: `agent_summary_includes_versions_for_install_actions`.

### D2: Agents page had no catalog-empty state and no safe rendering

- Target: `frontend/desktop/src/views/AgentsView.tsx`,
  `frontend/desktop/src/views/AgentsView.stories.tsx`,
  `frontend/desktop/src/styles.css`.
- Adds the catalog status strip, catalog-missing empty state, safe version
  access, row-level actions, and stories for missing catalog/versions/failed job.
- Global Refresh now reloads agents: `frontend/desktop/src/Desktop.tsx`.

### D3: Assistant action buttons were unstyled

- Target: `frontend/desktop/src/views/AssistantView.tsx`.
- Header and modal actions now use the shared `button button-secondary` classes.

### D4: App daemon fallback and macOS window reopen

- Target: `crates/agentdesktop/src/main.rs` — `ensure_desktop_daemon`,
  `run_desktop`.
- A system LaunchDaemon that exists but does not answer `/v1/health` (launchd
  starts it without `HOME`) no longer suppresses the user-level daemon.
- `RunEvent::Reopen` now shows the hidden main window on macOS.
