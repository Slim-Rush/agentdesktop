# Test Cases: STORY-202610260c7300b0bf28 — User-level agent jobs

## TC-01: Only cataloged agents can be installed and jobs bind the catalog (AC1)

- **Given** a job for a cataloged agent, a job for an id not in the catalog, and a job whose `catalog_revision`/`catalog_hash` no longer matches the daemon's verified catalog
- **When** the daemon receives all three
- **Then** the cataloged job proceeds, the unknown job fails with `unknown_agent`, and the stale-binding job fails with `catalog_changed` before any download or write

## TC-02: Verification failure aborts before execution (AC2)

- **Given** an artifact whose SHA-256 or Ed25519 signature does not match the catalog entry
- **When** the daemon downloads it
- **Then** it reports `checksum_mismatch` or `signature_invalid`, deletes the temp artifact, and leaves the previous install and receipt unchanged

## TC-03: Installation stays user-level (AC3)

- **Given** a macOS user without administrator rights
- **When** a valid install job runs
- **Then** files are written only under `~/Applications`, `~/.local/bin`, and the daemon state directory, no `sudo` or Installer authorization is requested, and a system-path target is refused

## TC-04: Install, upgrade, and crash recovery are consistent (AC4)

- **Given** version 1 installed, a job for version 2, a repeat of version 2, and a crash injected after payload publish but before the receipt write
- **When** the jobs and recovery run
- **Then** version 2 is published only after successful staging, the repeat returns `unchanged` only when detection and receipt integrity pass, the crash restores version 1, and a crash after the receipt write finishes cleanup without a mixed state

## TC-05: The lifecycle handles duplicates, cancellation, expiry, and late results (AC5)

- **Given** two jobs delivered concurrently, a queued cancel, a running cancel, an unacknowledged dispatch past its deadline, and a late result from an older attempt
- **When** the daemon and controller process them
- **Then** only one executes, the queued job becomes `cancelled`, the running job cancels only before the commit point, the unacknowledged job expires, and the late result is recorded as stale without changing the state

## TC-06: Uninstall verifies the current object and respects ownership (AC6)

- **Given** a managed agent with unchanged receipted paths, a managed agent whose launcher was replaced by the user, a user-installed agent, and a dry-run request
- **When** uninstall is requested for each
- **Then** unchanged paths are removed, the replaced launcher returns `conflict` without `allow_modified`, the user-installed agent is refused, and the dry-run lists paths without deleting them

## TC-07: Failures are actionable (AC7)

- **Given** a download timeout, a permission error, and a disk-full condition
- **When** each job fails
- **Then** the status contains a stable code, a redacted message, a bounded stderr tail, an environment snapshot, and a retryable flag

## TC-08: Unsupported platforms cannot receive install jobs (AC8)

- **Given** a Windows or Linux daemon without `user_install_macos`
- **When** an install job is attempted
- **Then** the controller disables the action and the daemon rejects the job as unsupported

## TC-09: The job path is covered by tests (AC9)

- **Given** the Story's test suite
- **When** it runs without network access
- **Then** state transitions, idempotency, verification failures, traversal/symlink rejection, cross-file crash recovery, receipt conflict, uninstall refusal, dry-run, and diagnostics are covered and pass

## TC-10: Admin and local origins are authenticated and attributed (AC10)

- **Given** no admin auth configuration, a verified OIDC administrator with the operator role, an administrator without the role, a plain spoofed `X-User` header, and a local OS user
- **When** each attempts to enqueue or run an install
- **Then** the unauthenticated/spoofed/roleless requests are denied and audited, the operator is allowed with `requested_by` set to the verified issuer+subject, and the local user can install a cataloged agent through the local API with `requested_by` set to the local uid
