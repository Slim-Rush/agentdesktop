# Test Cases: STORY-20261026ae47f2938d17 — Chat-based failure diagnosis using local coding agents

## TC-01: Chat opens with redacted job context (AC1)

- **Given** a failed job whose diagnostics contain a home path and a token-like value
- **When** the assistant opens for that job
- **Then** the context preview shows the job id, agent id/version, action, state, stable error code, and redacted diagnostics, and the user can leave before sending

## TC-02: The provider uses the local agent's model configuration (AC2)

- **Given** an installed Claude Code discovery entry with a verified no-tools mode
- **When** the user selects it and sends a message
- **Then** the app invokes the discovered executable with an allowlisted argv array and no new gateway/model/API-key setting, and no shell participates

## TC-03: Unsupported or unavailable providers fall back (AC3)

- **Given** no installed provider with a verified read-only profile
- **When** the assistant opens
- **Then** the UI offers rule-based diagnosis and does not spawn any executable

## TC-04: Read tools are bounded and redacted (AC4)

- **Given** a chat session for a failed job
- **When** the assistant builds context from jobs, catalog agents, and sync status
- **Then** only redacted read data is provided, within fixed size limits, with no file contents, environment variables, or secret values

## TC-05: Actions require allowlist and confirmation (AC5)

- **Given** a model response proposing `retry_install` and an unknown action
- **When** the user reviews the action cards
- **Then** the known action opens a confirmation step and calls the daemon only after confirmation, while the unknown action is ignored

## TC-06: Playbooks map stable error codes (AC6)

- **Given** each stable error code
- **When** the assistant explains it
- **Then** it offers exactly the mapped suggested actions for the failed job’s action, and no unrelated action

## TC-07: UI states and keyboard access are complete (AC7)

- **Given** loading, error, retry, provider-unavailable, and action-confirmation states
- **When** each is navigated by keyboard
- **Then** focus is managed, new messages and actions are announced through `aria-live`, and the confirmation modal traps and restores focus

## TC-08: Audit and tests cover the assistant path (AC8)

- **Given** the Story’s test suite with a fake provider executable
- **When** it runs
- **Then** argv construction, timeout, output cap, redaction, playbook mapping, confirmation, fallback, and audit records are covered, and no real model is called
