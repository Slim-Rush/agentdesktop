# Test Cases: STORY-2026102757b539fe89bc — Device identity lifecycle QA remediation

## TC-01: Loopback write requires the CSRF header (AC1)

- **Given** a controller with no `adminAuth` and a loopback admin listener
- **When** the UI sends a lifecycle POST with `x-agentdesktop-admin: 1`
- **Then** the transition succeeds with the actor `local#loopback-admin`, and the same POST without the header returns `403` without changing state

## TC-02: Configured admin auth still wins (AC2)

- **Given** `adminAuth` with a non-empty allowlist
- **When** a lifecycle POST omits the bearer token or uses a disallowed subject
- **Then** the request is rejected, and a valid allowed bearer token succeeds

## TC-03: Enrollment inputs are bounded (AC3)

- **Given** an enrollment begin request with a 4 MiB previous device ID or a 256-byte hostname
- **When** the controller validates it
- **Then** the oversized previous ID is ignored and not stored, the oversized hostname is rejected, and a valid 128-byte previous ID is retained

## TC-04: Rejection audit does not pollute another device (AC4)

- **Given** subject B presents subject A's device ID
- **When** the link is rejected and the enrollment continues
- **Then** the rejection has an empty device ID and does not appear in device A's audit history, while subject B's audit filter still returns it

## TC-05: Link decisions are fail-closed (AC5)

- **Given** a previous device with state `quarantined` or with `supersededBy` already set
- **When** an enrollment presents it
- **Then** the controller writes `state_unknown` or `already_superseded`, creates no lineage, and does not retire the previous device

## TC-06: Concurrent retires audit once (AC6)

- **Given** two concurrent requests to retire the same active device
- **When** both complete
- **Then** one reports `changed: true`, the other reports `changed: false`, and exactly one `device.retired` audit event exists

## TC-07: UI shows audit load-more failures (AC7)

- **Given** an audit page with a next cursor
- **When** the load-more request fails
- **Then** the audit section shows the error and the lifecycle dialog error remains empty

## TC-08: Daemon stops retrying a device-limit rejection (AC8)

- **Given** an enrollment that returns `ResourceExhausted` with `device_limit_reached`
- **When** the daemon handles it
- **Then** the enrollment state is `deviceLimitReached`, no further backoff attempts occur, the desktop snapshot is `rejected` with the limit message, and a logout request returns the daemon to a retryable state

## TC-09: The remediation suite is green (AC9)

- **Given** the Story's controller, agent, and frontend suites
- **When** they run without real OIDC or network access
- **Then** all new tests and stories pass and the existing lifecycle tests remain green
